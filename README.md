# OS-sol-checker

Проект системы проверки решений задач по операционным системам на C.
Задания, тесты и подсказки берутся из [OS-tasks](https://github.com/kr0sh512/OS-tasks).

**Текущий результат — спецификация и структура для следующих ИИ-агентов.**
Приложение не реализовано: Python-файлы содержат только описания назначения,
HTML/JS/CSS и Dockerfile/YAML — комментарии-заготовки. Нет работающего сервера,
сборки решений, миграций, образов или готового развёртывания.

## Требуемое поведение

- Навигация по темам и задачам, безопасный Markdown, независимые скрытые подсказки.
- Приём только `.c` до **102400 байт включительно**, UUID каждой принятой посылки.
- Запоминание имени, учебной группы и последней посылки по задаче через cookie-сессию.
- Временная БД всех принятых отправок; мгновенный результат для проверенного дубликата.
- Инвалидация результатов при изменении любого каталога `tests`.
- Постоянный архив успешных исходников: уникальность SHA-256 + размер, связи с задачами.
- Компиляция и запуск в gVisor без доступа к сети, хосту, тестовому репозиторию и секретам.
- Глобальная очередь, не более N sandbox одновременно, общий активный deadline до минуты.
- Раздельные ошибки размера, компиляции и исполнения; остановка на первом провале теста.
- Контейнерное развёртывание в Kubernetes после реализации и проверки изоляции.

## Выбранная архитектура

Python 3.12+ / FastAPI / Jinja2 / небольшой JavaScript; PostgreSQL для временной
очереди и результатов и отдельной постоянной базы архива; Kubernetes + gVisor
для одноразовых sandbox. Отдельный брокер очереди и SPA не требуются.

## Структура

```text
src/os_sol_checker/
  domain/                 модели, состояния и сменяемые политики
  application/            сценарии каталога, посылок, проверки, архива и сессий
  ports/                  контракты хранилищ, каталога, очереди и песочницы
  adapters/
    catalog/              Git, Markdown, tests fingerprint
    postgres/             временная БД, архив, сессии и очередь
    kubernetes/           жизненный цикл sandbox Pod
  worker/                 singleton scheduler, N слотов и восстановление
  web/
    templates/            серверные страницы
    static/               минимальные JavaScript и CSS
sandbox/                  изолированные compile/run stage
migrations/
  transient/              будущие миграции временной БД
  archive/                будущие миграции постоянного архива
deploy/
  containers/             заготовки application/compiler/runner Dockerfile
  kubernetes/             заготовки workloads, RBAC, policy, quotas и storage
tests/                    места для будущих unit/integration/e2e/security проверок
docs/                     спецификация и план реализации
```

`pyproject.toml` содержит только метаданные пакета, без runtime-зависимостей и
entry points. `.env.example` задаёт проектные значения, но загрузчика конфигурации
пока нет. Реальные секреты и файлы посылок в VCS не хранятся.

## Начало следующего этапа

Читать архитектуру и план реализации; затем реализовать домен и каталог.
Команд запуска пока нет. Не применять заготовки YAML и не собирать пустые Dockerfile.
Обычный Docker не является допустимой заменой песочницы.

Система контроля версий — **Jujutsu**; репозиторий уже инициализирован.
Использовать `jj status`, `jj diff`, `jj describe`; Git нужен приложению только
для чтения внешнего репозитория заданий.
