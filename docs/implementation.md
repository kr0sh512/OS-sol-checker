# План реализации для следующих агентов

## Что уже сделано

Только документация, метаданные пакета и файлы-пустышки. Нет работающего HTTP, SQL, компиляции, очереди, Docker image или Kubernetes deployment. Ничего не запускать на студенческих посылках до проверки всей границы изоляции. Нет фиктивных тестов, выдающих отсутствие реализации за успех.

Все требования пользователя обязательны; этапы ниже — порядок работы, не сокращение объёма. Перед изменением публичного контракта согласовать и обновить связанные документы и вызывающие модули. Текущие имена файлов задают границы ответственности, но не требуют класса на каждый файл.

## Порядок работ и передача контрактов

### 1. Домен, конфигурация и каталог

Файлы: `domain/`, `ports/`, `config.py`, `adapters/catalog/`, `application/catalog.py`.

- Определить DTO и состояния из architecture/submissions, настройки из `.env.example` с fail-fast проверкой обязательных параметров.
- Реализовать immutable catalog, импорт Git, tests fingerprint, task/topic id, Markdown и подсказки по [catalog.md](catalog.md).
- Выбрать зависимости указанного стека, записать реальные версии в `pyproject.toml` и lock-файл. Добавить настоящие entry points только вместе с их реализацией.
- Передать DTO каталога, контекст проверки, порты и fixtures этапам 2–4.
- Smoke: импортировать исследованный upstream commit; получить одну активную задачу, две пары пустых тестов, две подсказки и неактивную заготовку второй задачи. Не считать пустые upstream-тесты доказательством корректного judge.

### 2. Хранилища, сессии и приём посылок

Файлы: `migrations/`, `adapters/postgres/`, `application/submissions.py`, `application/sessions.py`, `application/archive.py`.

- Независимые миграции transient/archive, роли и lifecycle. Источники до 100 КиБ хранить в BYTEA; уникальность и concurrency enforce через БД, а не check-then-insert.
- Реализовать приём/кэш/in-flight followers, отдельный UUID каждой принятой отправки, session ownership, очередь и versioned invalidation.
- Реализовать идемпотентную запись архива с повторным завершением после сбоя между двумя БД. Ни чужой автор, ни архивный успех не должны подменять новый результат проверки.
- Smoke на настоящем PostgreSQL: две конкурентные одинаковые отправки, разные UUID и одна работа; archive dedup с двумя авторскими фактами; смена tests очищает результаты, но сохраняет профиль и архив. Проверить перезапуск в archive_pending.

### 3. Песочница и планировщик

Файлы: `sandbox/`, `adapters/kubernetes/`, `application/judging.py`, `worker/`, compiler/runner Dockerfile, sandbox/admission/RBAC/network/quota manifests.

- Реализовать bounded транспорт, компиляцию и запуск по [security.md](security.md). Не выполнять даже тестовый пользовательский C-код на хосте.
- Подготовить execution nodes: runsc, CNI enforcement, PID limit, независимый watchdog. Проверить совместимость нужных syscall.
- Реализовать singleton scheduler, N слотов, завершение stage сразу после результата, общий deadline и восстановление после потери worker.
- Smoke в реальном gVisor: корректный C, ошибка сборки, бесконечный цикл, превышение output, неправильный первый тест; подтвердить Pod cleanup. Не заменять smoke моками Kubernetes API.
- Только после доказанной изоляции разрешить этапу 4 отправлять код через web.

### 4. HTTP и интерфейс

Файлы: `main.py`, `web/`, application Dockerfile; серверный Jinja и небольшой JavaScript без SPA.

- Реализовать маршруты, схемы ответа и коды ошибок по [submissions.md](submissions.md).
- Главная → тема → задача; безопасный Markdown, независимые свёрнутые подсказки, профиль, upload, статус и первый провал. Обновление страницы сохраняет контекст сессии.
- Streaming file/body limits, cookies, CSRF/Origin, авторизация посылок, escaped diagnostics.
- Smoke через настоящий браузер: сохранить имя/группу; открыть/закрыть две подсказки независимо; отправить .c; увидеть UUID, очередь и результат; перезагрузить страницу; повторить отправку и получить cache hit без нового sandbox. Проверить узкий экран и keyboard navigation.

### 5. Контейнеры и кластер целиком

Файлы: `deploy/`, health endpoints и эксплуатационная инструкция в README/docs.

- Заменить comment-only Dockerfile/YAML настоящими образами и manifests; фиксировать digests. Разделить доступ web, worker, sync и sandbox.
- Настроить ephemeral transient DB, persistent archive, secrets, HTTPS, ingress body limit, readiness и backup/restore архива.
- Поднять систему с нуля в целевом кластере, пройти end-to-end сценарии ниже и записать наблюдаемые результаты. Пакет без runtime-зависимостей и пустые manifests не являются deployable-артефактами.

## Приёмочные сценарии

Это требования к будущим проверкам, не уже выполненные тесты. Постоянные регрессионные тесты нужны для видимых пользователю границ и переходов; wiring и наличие имён/файлов тестами не закреплять.

| Область | Сценарий и ожидаемый результат |
| --- | --- |
| Формат каталога | Пробелы/Unicode в темах; natural order 1, 2, 10; `.gitkeep` не создаёт проверяемую задачу; непарный тест не допускает пустую успешную проверку. |
| Подсказки | Два top-level `---` создают две независимо закрытые подсказки; `---` внутри C/Markdown code fence и inline-текста не делит описание; raw HTML/XSS не исполняется. |
| Файл | 102400 байт принимается, 102401 отклоняется 413; слишком большой multipart без Content-Length тоже останавливается; `.C`, два файла и подмена пути не проходят. Невалидный C даёт compile_error, не HTTP 500. |
| Учёт | Каждая принятая отправка имеет свой UUID, имя/группу на момент приёма, hash/size/task/context/result. Смена профиля не переписывает старого автора. |
| Кэш | Одинаковые байты/задача/generation/policy возвращают результат сразу; новая задача, изменённый тест, flags/image/limits/comparator не используют чужой ключ. Между пользователями не раскрываются чужие данные. |
| Очередь | N+1 различных посылок: одновременно не более N sandbox, лишняя ждёт. Переполненная очередь отклоняет новый приём; follower одинакового решения не создаёт лишний Pod. |
| Первая ошибка | Тест 1 пройден, тест 2 неверен, тест 3 не запускается. Результат содержит номер 2, bounded expected/actual/stderr и корректный passed_tests. |
| Причины | Отдельно compile_error, compile_timeout, run_timeout, runtime_error, memory_limit, output_limit, wrong_answer и общий submission_timeout; инфраструктурная недоступность не становится ошибкой студента и не кэшируется. |
| Сеть и диск | В sandbox не читаются хост/БД/тесты/чужие исходники; отсутствуют DNS и доступ к интернету, metadata/API/соседям по IPv4/IPv6. Read-only rootfs и tmpfs limit действуют. |
| Процессы | Fork bomb ограничена всей cgroup; fork/setsid/потомок, переживающий main, не остаются после stage; stdout flood не расходует неограниченную память контроллера. |
| Жизненный цикл | Sandbox удаляется сразу после ответа; при потере attach/worker/БД/node connection срабатывает независимая остановка. Остановка не позже общего deadline подтверждается на execution node. Неизвестная остановка не освобождает слот. |
| Изменение tests | Изменение/добавление/удаление/переименование любого tests entry меняет generation; старые queued/running/archive_pending отменяются, кэш очищается, поздний результат не публикуется как актуальный. Профиль и постоянный архив остаются; смена поколения не ждёт доступности архива. |
| Изменение текста | Правка только task.md обновляет страницу без потери применимого кэша; старая ревизия остаётся в provenance посылки. |
| Архив | Успешные исходные байты сохраняются один раз по hash+size; связь с новой задачей сохраняется отдельно; повтор другого автора не перезаписывает первого. Архивный успех, в том числе поздний commit со старым контекстом, не означает accepted при новых тестах. |
| Сбой двух БД | Сбой после archive upsert и до transient finish не дублирует исходник/receipt после восстановления; недоступный архив не даёт неподтверждённый финальный accepted. |
| Сессии | Reload сохраняет имя/группу и last submission; UUID чужой сессии недоступен. Истёкшая transient-запись отображается как недоступная история. CSRF и cookie tampering не меняют результат или профиль. |
| Развёртывание | Нет runsc/CNI/PID/watchdog/admission → readiness false, запуска кода нет. Перезапуск transient не теряет постоянный архив; восстановление архива проверено. |

## Проверка именно этой заготовки

Достаточно проверить TOML-синтаксис метаданных, наличие и связность указанных путей, отсутствие исполняемой логики в Python/JS, отсутствие ресурсов в comment-only manifests и согласованность `.env.example` с архитектурой. Запускать отсутствующий сервер, pytest без тестов, сборку пустого Dockerfile или `kubectl apply` комментариев не нужно: это не проверяет заданное поведение.

Результаты такой структурной проверки не распространяются на будущую безопасность, HTTP или работу C-решений. После реализации обязательны отдельные настоящие smoke-сценарии каждого этапа.
