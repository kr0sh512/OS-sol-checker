# Работа над OS-sol-checker

Сейчас здесь только структура и спецификация. Не описывать заготовки как работающую систему.

## Перед реализацией

1. Читать README.md, затем docs/architecture.md и профильную спецификацию.
2. Работать по этапам docs/implementation.md; не менять контракты соседнего модуля молча.
3. Использовать Jujutsu: `jj status`, `jj diff`, `jj describe`; не делать `git init`, `git add` или `git commit`. Репозиторий заданий можно читать Git-клиентом как внешний источник данных.
4. Файлы-пустышки заменяются настоящей реализацией, а не слоями совместимости с пустышками. Зависимости выбрать и зафиксировать при реализации; сейчас pyproject не содержит runtime-зависимостей.

## Инварианты

- Никакого выполнения пользовательского кода или компиляции в web/worker либо тестах на хосте: только дочерние nsjail внутри отдельного runner-контейнера.
- Нет небезопасного fallback при недоступной изоляции. Нельзя ослаблять сеть/диск/права ради теста; runner не получает Docker socket и не создаёт контейнеры.
- Один активный scheduler и один runner, глобальный предел N, авторитетный семафор runner и подтверждённая уборка перед освобождением слота.
- Все результаты привязаны к generation и judge policy; постоянный архив не заменяет свежую проверку.
- Ровно 102400 байт допускается; проверять исходные байты и не доверять имени файла.
- UUID не заменяет авторизацию по сессии. Имя/группа не являются подтверждённой личностью.
- Документацию и затронутые контракты обновлять вместе с кодом. Не подменять испытание реальной песочницы моками.
- Основное описание развёртывания — корневой `docker-compose.yml`; topology, host prerequisites и раздельные права сервисов заданы в docs/deployment.md. Не добавлять альтернативный оркестратор.
- Контейнер runner и дочерний jail — разные границы: служебные токены, API, cgroups и файловые данные контроллера недоступны решению. `privileged: true` и unconfined-профили не включать по умолчанию.

## Готовность

Нужны реальные smoke-сценарии и проверки из docs/implementation.md. Само наличие Dockerfile, YAML, классов или успешно импортируемого пакета не означает готовность приложения или безопасность песочницы.
